# Admin UI (`app/admin/`)

Vanilla-JS SPA, **no build step**: `index.html` + one `css/style.css` + three JS files. `app/main.py` mounts `/admin/css` and `/admin/js` as StaticFiles and serves `index.html` with `{{BASE_PATH}}` substituted from `settings.root_path`, so edits are live on the next hard-refresh — no restart, no rebuild. Because the whole `js/` directory is mounted, adding a file needs no `main.py` change — only a `<script>` tag in `index.html`.

- `js/app.js` — shell, shared helpers, and most sections.
- `js/usage_report.js` — the API Usage Report section only. Loads **after** `app.js` and relies on its globals (`api()`, `esc()`, `toast()`, `currentUser`, `syntaxHighlight()`, `registerCopyPayload()`/`copyPayload()`). It exists as a separate file because `app.js` had already grown past 2000 lines and this section is self-contained.
- `js/mcp_tools.js` — the MCP Tools section only, same split and the same dependency on `app.js` globals.

Conventions inside `app.js`:

- `navigateTo(page)` maps a sidebar `data-page` key to a `render*()` function and a title; every page renders its HTML into `#contentArea`.
- Shared helpers: `api(method, path, body)` (auth header + error unwrapping), `dbPrefix()` (current `/{alias}` segment), `esc()` for **all** interpolated values, `toast()`, `openModal()/closeModal()`.
- Most sections use modals for create/edit; **SQL Definitions and API Usage Report are the exceptions** — their list/detail views are full pages via `enterSqlDefView()` / `enterUsageView()`. Follow the neighbouring section's pattern rather than mixing both in one section.
- **SQL Definitions' list view is a two-pane `.split-list`**: groups on the left sorted by name, the selected group's definitions on the right sorted by name. Grouping is on `group_name` (free text on the definition), **not** on `permission`. `GET /{db}/queries/definitions` returns registry order, so **both orderings are imposed client-side** in `renderSqlDefs()`. `sqlDefGroup` holds the selection across a detail round-trip and is reset when the current database has no such group; `paintSqlDefGroups()` / `paintSqlDefTable()` repaint the panes without refetching. An empty `group_name` is valid and buckets under `SQL_DEF_UNGROUPED`.
- **The create form derives Name and Permission from the Group.** `applySqlDefGroupPrefix()` keeps `<group>_` at the front of Name, `syncSqlDefPermission()` keeps Permission at `query:<name>`. Both are one-way: `sqlDefPrefix` / `sqlDefAutoPerm` record what the code last wrote, so once the user edits either field by hand it is never rewritten. Permission left empty still auto-generates server-side — the prefill only makes that value visible.
- **API Usage Report and MCP Tools are superuser-only.** `showApp()` hides `#navUsageReport` / `#navMcpTools` for everyone else; the backend's `get_current_active_superuser` remains the authority.
- **MCP Tools is read-only by design.** It reports the tool names the MCP server derives, including definitions it silently drops on a name collision. It configures nothing — the MCP server is a separate process driven by `MCP_*` env vars, so there is nothing here to write to. Do not grow it into a settings page.
- **Login page has two paths.** `window.__SSO_ENABLED__` (injected by `admin_spa()` alongside `{{BASE_PATH}}`) decides whether `#ssoBlock` is unhidden; the password form is always present so a broken isap-auth never locks admins out. `consumeSsoFragment()` runs first in the `DOMContentLoaded` handler, reads `#sso_token=` / `#sso_error=` left by `GET /api/v1/auth/sso/callback`, and clears it with `history.replaceState` so the JWT does not survive a reload. The `SSO_ERRORS` keys must stay in sync with the `sso_error=` slugs in `app/api/v1/auth.py`.
- Playwright specs in `tests/e2e/` cover the Query Console, raw-JSON copy buttons, the API Usage Report and the SSO login surface; run them after non-trivial Admin UI changes.
